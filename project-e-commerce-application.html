E-commerce Application

A Flutter shopping application that lets users create an account or sign in, discover products, browse categories, search by title, inspect product details and manage a shopping cart. The app uses REST API data, Cubit/BLoC state management and local storage for cart data and authentication tokens.

Project overview

The app presents a product-discovery flow inspired by modern shopping applications. The home screen retrieves products and categories from the EscuelaJS Fake Store API, while category selection and keyword search help users narrow the catalog. Selecting a product opens a dedicated details page showing its image, title, description and price.

Users can add products to a cart, adjust quantities and remove items. Cart data is serialized and stored locally so it can be restored when the app is reopened. Login and registration use API endpoints, while tokens returned after login are saved securely on the device.

Key features

  • Register a new account and sign in through the REST API, with input validation on authentication forms.
  • Load and browse products from the API, with category filtering and an All category.
  • Search the catalog by product title.
  • Open a product details screen with product image, title, description and price.
  • Add products to the cart, increase or decrease quantities, and remove items.
  • Persist cart contents in SharedPreferences so cart items can be restored after reopening the app.
  • Store access and refresh tokens with flutter_secure_storage after a successful login.
  • Navigate between Home, Cart and Account through the bottom navigation bar.
  • Show an account area, sample address-book entries and a logout action.
  • Use responsive sizing with Flutter ScreenUtil and reusable UI components.

API integration

The application uses the EscuelaJS Fake Store API as its remote data source.

Base URL: https://api.escuelajs.co/api/v1/

  • GET /products — retrieve the product catalog.
  • GET /categories — retrieve product categories.
  • GET /categories/{id}/products — retrieve products for a selected category.
  • GET /products?title={query} — search by product title.
  • POST /users — register an account.
  • POST /auth/login — authenticate a user.

API requests are handled through Dio and the project repository layer. No API key is configured in the supplied source. API availability and behavior depend on the external service.

Local storage and current scope

The cart repository saves cart items as JSON in SharedPreferences, including product ID, title, price, image URL and quantity. Access and refresh tokens returned after login are stored using flutter_secure_storage. Products and categories are retrieved from the remote API.

Current limitations: the checkout button is a UI entry point only; payment and order processing are not connected. The subtotal, VAT, shipping and total shown in the cart are sample values. The addresses shown in the address screen are sample UI entries.

Architecture and code organization

The codebase is separated into a shared Core layer and feature-oriented Features directories. Core contains networking, routing, shared styling, service location and storage helpers. Feature directories organize authentication, product discovery, product details, cart, account, address book and splash functionality.

Cubits manage authentication, categories, products and cart state. Repository classes keep data operations separate from screen widgets, while shared theme and UI components support consistency across screens.
